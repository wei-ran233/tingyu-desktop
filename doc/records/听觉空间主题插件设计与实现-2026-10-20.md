# 听觉空间：动态主题插件设计与实现

## 目标和设计取舍

将原来的单纯换色扩展为可选择、可保存、可退出的页面外观插件。插件 ID 为 `lx.theme-studio`，提供潮汐、信号、花间三套主题，覆盖颜色、动态背景、导航布局、播放器外观、详情构图以及部分页面的展示方式。

用户进一步要求接管 Logo、图标和页面设计后，实施了第二轮重构：主题包更新为 `1.1.0`，增加 `appearance.identity`、三套 Logo、主题 SVG 图标系统，以及八类功能各三种主题渲染，共 24 个新渲染注册。功能总数仍为 33，渲染注册总数为 90，设置贡献仍为 17。

用户已明确“图表”为笔误，实际要求为“图标”；本轮没有增加统计图表。背景中的波纹和扫描线是装饰图形。

视觉围绕音乐的空间感、录音设备和唱片封套设计。三套主题分别把个性集中在海面流光、仪表式控制台、植物剪影上；不为每个控件增加独立动画。背景采用宿主 CSS 与几何图形，无外部图片、字体下载或渲染网络依赖。

## 插件契约

插件 API 升级为 `1.1.0`，继续兼容声明最低版本 `1.0.0` 的已有插件。新主题包声明最低 `1.1.0`。

- `theme.contribute` 允许贡献语义颜色变量。
- `theme.appearance` 允许贡献经过校验的外观方案。
- `themes[].appearance` 声明 `layout`、`background`、`detail`、`content` 和可选的 `views`。布局、背景与详情样式采用宿主支持的枚举，渲染引用采用已注册的功能与视图标识。
- `appearance.identity` 选择 Logo、导航与操作图标体系。SVG 引用采用响应式命名空间，退出主题后恢复原图标；不使用 DOM 扫描或 MutationObserver 修改页面。主题渲染带有身份约束，未启用对应主题时不能被单独选中而导致配色与控件错配。
- 外观方案和主题描述纳入原有 Ed25519 签名。安装时拒绝非法枚举、未知外观字段、重复主题 ID、越界视图引用及危险变量值。
- 主题包不需要歌单读取、播放控制、文件读写或任意 IPC 权限。展示调整继续使用现有功能模型，不直接替换播放器或修改歌单。

颜色仍通过 `--lx-*` 语义变量传递；新增兼容派生覆盖旧页面使用的文本、导航、按钮、选择态、分隔线和色阶变量。隔离集合视图继续接收主题快照。

主题指定的渲染方式是临时覆盖层，不写入 `lx.features.v1`。例如信号使用设备面板式设置页与简洁电台对话视图；退出主题后恢复用户此前的页面渲染选择。不存在的视图引用回退到用户原有选择。

选择主题时先异步准备所需模板，准备完成后统一发布颜色、身份和渲染覆盖，避免可交互页面先显示旧模板再被替换。准备失败时保持此前外观；准备期间点击恢复默认，也不会被迟到的加载结果重新切回主题。预加载只读取功能定义与模板，不运行功能的组件 setup；切换渲染继续保留同一功能模型。

第二轮中，搜索、资料库、排行榜、歌单、设置、下载、播放器、播放详情均拥有专属主题渲染。信号额外选择电台的简洁对话视图。资料库与在线结果继续使用虚拟列表，并按主题调整行高、封面和排版。保留原模型中的播放、批量操作、分页及右键菜单。

潮汐以宽侧栏、大幅横向标题、封套式音轨行和圆形唱片详情为中心；信号采用设备导轨、右侧目录、紧凑音轨及两行播放控制台；花间采用横向主导航、侧边竖排标题、横向歌单目录、唱片册排版，评论在详情页下方展开。

## 使用与恢复

侧栏或横向导航中的「主题工作室」进入 `/themes`，点击主题立即应用。设置的基础外观和插件管理也提供入口。主题选择与动态背景开关分别保存在本地。

「恢复默认外观」清除主题选择、动态背景图层、布局属性与渲染覆盖；保留歌单、队列和功能配置。插件管理中禁用或卸载正在使用的主题包，同样恢复基础外观。重新启用包不会自动夺回当前界面。

基础设置中选择旧配色，或执行「恢复默认功能和原版布局」，也会退出动态主题。

动态背景开关独立保存。系统减少动态效果、软件关闭动画、页面不可见时，背景停止运动。信号的仪表动画跟随播放/暂停状态，仅用于视觉律动，不作为真实音频频谱测量。

主题工作室和插件恢复页属于宿主，在官方功能包停用时仍可进入。主题插件本身可以按普通插件启停和卸载。

主题的完整页面构图作用于本轮列出的原生功能渲染。隔离的第三方页面可接收语义颜色快照，其内部页面结构仍由该页面自己的渲染器负责。当前外观契约选择宿主已支持的设计方案，不执行主题包任意 JavaScript、CSS 或 SVG；新增另一套完整设计时，需要增加并审核相应的宿主渲染与图标定义。

## 源码与产物

- 包清单：`plugin-samples/theme-studio/manifest.json`
- 构建产物：`src/static/plugins/lx.theme-studio.lxplugin`
- 外观契约：`src/common/theme/appearance.ts`
- 颜色兼容：`src/common/theme/compatibility.ts`
- 运行时：`src/renderer/core/theme.ts`、`src/renderer/core/theme/state.ts`
- 选择页与背景组件：`src/renderer/components/theme/`
- 页面样式：`src/renderer/assets/styles/theme-appearance.less`
- 品牌、图标与完整页面设计：`src/renderer/core/theme/identity.ts`、`src/renderer/core/theme/icons.ts`、`src/renderer/assets/styles/theme-identities.less`
- 独立渲染模板：`src/renderer/bundles/official/renderers/themes/`

执行 `npm run build:plugins` 生成签名主题包；执行渲染进程及主进程构建，将新契约与主题包放入同一应用构建。仓库默认的开发样例密钥沿用既有插件流程，正式发布仍须使用项目规定的发布签名密钥。

本轮不替换系统已安装的应用。旧宿主需要升级到支持插件 API 1.1 的构建后，才能使用新的布局与动态背景契约。

## 验证入口

- `npm run test:theme`：主题权限、外观约束、危险值、图标身份、持久化、亮暗切换、禁用恢复、乱序请求与监听清理。
- `npm run test:features`：主题渲染覆盖保留模型和用户偏好，不可用视图正确回退。
- `npm run test:collection`：签名主题包、旧插件与版本兼容、安装/回退等现有契约。
- `npm run test:theme:app`：生产构建中的真实主题选择、页面显示、重新加载、禁用/恢复、窄窗口及截图。
- `LX_DETAIL_UI_ONLY=1 LX_DETAIL_THEME=tide npm run test:play-detail:live`：真实音乐接口下的主题详情、歌词、评论与播放流程；`signal`、`petals` 可分别复测。可用 `LX_DETAIL_EVIDENCE_DIR` 指定独立证据目录。

验证记录位于 `.runtime/theme-studio-20261020/`。本地列表截图使用测试歌名和临时 SQLite 数据；真实在线播放、歌词、评论的证据与这些展示夹具分别保存。
