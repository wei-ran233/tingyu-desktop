## 当前结构

```text
宿主
 ├─ 窗口、路由容器、主题、数据/设备适配器、受限 IPC
 ├─ 插件注册、签名验证、安装事务、独立恢复页面
 └─ LX 官方功能整合包 lx.official-suite（默认启用）
     ├─ function providers：功能状态、动作、订阅和生命周期
     ├─ rendering providers：模板与样式，按 featureId 绑定功能
     ├─ service provider：后台服务；不随页面渲染切换而重建
     ├─ pages：原有 8 个路由，包括歌单详情
     ├─ settings：16 个独立设置分组
     └─ 集成音乐集合官方列表、卡片示例包
```

官方功能定义位于 `src/renderer/bundles/official/features/`。页面和设置模板位于 `views/`，替代模板位于 `renderers/`。目录中的 Vue 文件通过外部脚本关联功能实现，顶层注册的视图本身只包含模板和样式。下载、列表等操作组合函数也迁出视图目录。

`registerFunction` 与 `registerFeatureView` 可分别贡献功能和渲染；`registerFeature` 是官方包同时声明二者的便利入口。渲染按需加载，注册后新增的渲染可以供已经挂载的功能选择。替代视图加载失败时保留默认视图和功能实例。

后台实现位于 `src/renderer/bundles/official/services/`。播放、同步、OpenAPI、歌词状态、更新、自定义来源 API、深链接和列表自动更新由独立服务组件加载。宿主 `core/useApp` 保留窗口、主题、路由恢复等基础启动工作。

现有原生主进程接口通过 `src/main/bundles/official/index.ts` 集中适配，生命周期仍为应用进程级。数据库、操作系统窗口、文件和音频设备等受信任适配器由宿主管理；下载的第三方脚本不能直接获得这些能力。停用整合包会卸载渲染进程服务的订阅、停止音频、暂停下载、关闭同步及 OpenAPI。原生接口的注册本身保留到进程退出。

## 覆盖范围与多渲染

- 32 个功能贡献：8 个页面、16 个设置分组、8 个播放器/工具栏/同步/更新等界面功能。
- 64 个渲染注册项：每个功能有默认和紧凑方式。大部分紧凑方式复用原模板并调整密度；这些不是 64 套不同设计。
- 设置主页额外提供页签模板，DJ 提供简洁对话模板，下载提供卡片模板。
- 音乐集合的列表/卡片仍使用隔离 WebContentsView 和同一宿主集合控制器。
- 单个已挂载功能切换渲染时复用同一功能组件实例和 setup 状态。路由离开、功能停用会按生命周期卸载。音乐集合的选择和查询另外由宿主控制器保存。

这里的本地功能提供器是随应用编译的受信任模块。其视图模型目前采用 Vue Options/setup 返回值作为内部契约，并通过应用构建摘要绑定版本。通用第三方业务逻辑的跨进程、版本化数据模型协议还没有开放；目前第三方运行时对外提供的是隔离的集合、页面、主题和受限存储协议。不能把本次工作描述为“任何功能 JS 都可以从下载包热插入主进程”。

## 默认整合包与恢复

`src/common/bundles/official.json` 是默认页面、设置和服务的清单。官方整合包激活文件位于 `plugin-samples/official-suite/`，构建为 `src/static/plugins/lx.official-suite.lxplugin`；功能代码编译进应用，其激活包不能单独替换编译代码。

主进程要求签名有效、签名密钥受宿主信任、插件 API 兼容、原生整合包构建摘要与应用一致，才会启用原生功能。应用更新会刷新已安装的旧官方激活包，仍保留签名密钥绑定和用户禁用状态。

新配置默认启用官方整合包与集合插件视图，默认保持现有页面和列表外观。既有明确保存的关闭偏好继续保留。功能开关和各功能渲染偏好分别保存。

宿主 `/extensions` 页面独立于官方设置插件。即使设置功能关闭、整合包关闭或卸载，仍可以进入恢复页面，启用或恢复官方整合包。卸载记录保存在插件注册表，重启不会自动重新安装；显式恢复可以重新加载应用附带的受信任整合包。

## 已发现并修复的漏洞

1. **渲染包装影响布局**：整页高度包装会把播放器/工具栏挤满容器。现在保留原视图根节点及其尺寸，仅合并渲染元数据和样式类。
2. **不同模板共用编译缓存**：Vue 模板缓存索引可能重叠。切换模板会清除该实例的模板缓存，并用渲染 ID 作为视图根 key 重建子树，避免跨模板的优化块比对；功能组件实例和功能状态保持。
3. **设置 ID 偏好丢失**：带下划线的设置标识被早期校验器丢弃。已统一允许这些标识，并限制偏好数量和长度。
4. **重复渲染注册静默覆盖**：校验同一批贡献内的重复 ID，并按功能作用域选择渲染，防止跨功能误用。
5. **旧激活包与新程序不匹配**：签名之外增加构建摘要约束和明确的不兼容原因；官方包随应用更新。
6. **卸载后重启自动装回**：增加持久化卸载记录和独立恢复动作。
7. **服务卸载后异步初始化继续播放**：数据初始化和启动恢复检查活动状态，卸载后停止后续初始化和自动播放。
8. **后台监听泄漏**：歌词状态监听与服务实例一起注销。现有播放、同步、更新等监听随服务组件卸载。
9. **构建顺序导致摘要陈旧**：开发、单项构建和契约测试前生成整合包及摘要；完整分发构建先生成正式签名包，再启动并行 webpack。
10. **开发签名误入分发构建**：完整 `npm run build` 要求外部发布私钥，公开示例私钥不能成为生产信任根。当前本地调试包采用示例密钥，仅用于开发验证。

11. **启动恢复覆盖用户导航**：此前挂载后异步恢复页面，会覆盖刚发生的导航。现在先读取历史路由并完成路由恢复，再挂载应用。
12. **宿主插件图标被来源策略拦截**：经签名验证且不超过 32 KiB 的图标通过受信任 IPC 转换成图片数据地址；插件文档继续维持严格的来源隔离。

13. **缓存的不可见视图仍能发起操作**：写操作和导航现在要求发送者属于当前可交互的可见视图，隐藏缓存不能继续执行命令。
14. **初始页面的模态目标尚未插入文档**：宿主先挂载 `#view` 容器，再挂载路由页面，保证 Teleport 目标存在，避免页面卸载时报空节点错误。
