## 结论与交付边界

原计划的总体分层可继续采用，但仅有接口列表不足以保证插件可以安全替换。需要补充并发、集合身份、选择语义、权限执行点、安装事务、资源访问与生命周期约束。

本轮推进控制器契约、网关接线、隔离运行时、恢复列表和安装回滚。实验开关默认关闭；尚不执行阶段 4 的默认切换。旧页面通过关闭实验开关保留，故障时启用独立的最小恢复列表。未安装或替换用户现有桌面程序。

## 设计漏洞与采用的修订

### 1. revision 的含义与并发执行必须明确

缺陷：请求进入时验证 revision，然后异步执行，不能阻止两个同时到达的删除命令都通过。重建控制器后从 1 开始还会接受旧视图遗留请求；读取完成时数据也可能已经变化。

修订：revision 在当前宿主渲染进程内单调分配，控制器重建不复用版本。命令串行化并在真正执行时复核版本；执行副作用前推进版本。分页、刷新、排序、过滤和选择变化推进版本。读取在异步操作前后验证同一版本，过期错误统一为 `STALE_SNAPSHOT`。播放指示和滚动锚点是展示状态，不使歌曲缓存和选项失效。

已实现并增加真实控制器测试。长期仍应为跨进程重启的操作设计 request ID 和幂等记录；对长耗时批处理需要任务协议，不能只延长 IPC 超时。

### 2. opaque key 应是宿主引用，不能编码内部 ID

缺陷：`source:id` 会公开内部 ID，本地歌曲 ID 还可能关联路径；只验证 key 的字符串形状不等于验证归属。

修订：适配器为歌曲分配随机引用，并在宿主索引中映射内部对象。控制器要求目标存在于该适配器；未知引用拒绝。播放指示由宿主转换为同一引用。摘要排除本地文件封面路径。

已实现。远程集合在服务端发生删除、重排或总量变化时，还需要来源版本/cursor 或显式失效规则，不能声称本地 revision 冻结了远程服务的数据。

### 3. 全选后取消一项与跨页命令必须有统一语义

缺陷：快照只有 none/some/all，不足以表达内部全选后的排除状态。如果插件自行保存选中 key，切换布局会丢失选择，多选超过 100 条还会突破消息限制。

修订：宿主内部使用“全选标志 + 排除集合”或“显式选择集合”。快照只返回模式和数量；每条 getItems 结果返回 selected。批量命令统一提交 `{kind:'selection'}`，由宿主跨页展开并应用排除。单项命令必须只有一个歌曲引用。

已实现控制器与通用适配器路径；新增 10,000 首、300 项选择和四种跨页批量命令测试。排序/过滤影响集合成员时应明确重置选择；纯翻页保留选择。

### 4. option ID 必须绑定上下文，权限必须逐次执行

缺陷：下载音质或歌单 ID 虽然在白名单中，也不意味着可以跨歌曲、跨命令复用；声明权限不等于实际限制了调用。

修订：宿主返回临时 opaque option ID，绑定 revision、命令和目标；提交时再转换为内部选项，伪造、跨目标和过期选项拒绝。请求入口按 manifest 核对读取、命令、导航与存储权限，并验证 sender 为已绑定视图的主 frame。下载执行还检查宿主开关。

已实现。当前命令授权仍以 `collection.commands` 为粒度；未来若引入无人值守插件，应拆分写入、下载和破坏性命令权限，并在更新权限扩大时明确提示。

### 5. 隔离需要贯通 session、协议、IPC 与视图所有者

缺陷：在默认 session 注册协议，无法供自定义 session 使用；仅靠 CSP 不能代替网络隔离。旧组件异步 hide/bounds 请求还可能遮挡新页面。原有发送端使用 send，接收端使用 handle，两端根本未构成往返通信。

修订：插件按 ID 使用内存 session；在同一 session 注册协议并限制插件资源归属，拒绝外部请求、权限、弹窗、跳转和下载。宿主按 sender 身份绑定窄化 API。使用 invoke/handle 贯通响应、快照和主题。每个宿主占位组件有 ownerId，过期 owner 的 hide/bounds 无效；快照同时核对 provider 身份。

已实现。Electron 官方说明协议按 session 注册：[protocol 文档](https://www.electronjs.org/docs/latest/api/protocol/#using-protocol-with-a-custom-partition-or-session)。

### 6. 视图缓存必须有预算，恢复状态应属于宿主

缺陷：要求会话内保留视图却没有定义内存上限，会让多个页面、上下文和插件无限累积。销毁实例后再创建也不能自然保存选择和锚点。

修订：宿主会话缓存最多 8 个控制器，视图缓存最多 4 个 WebContentsView，按最近使用淘汰。控制器独立于 provider，保存查询、选择和以歌曲偏移表示的锚点。缓存命中复用视图，重新显示后通过可用状态事件刷新。两次崩溃触发熔断，第一次自动重建，显式重试清理熔断记录。

已实现基础路径。预算需要真实设备内存与频繁切换测试再调优，不能把保留所有历史上下文作为保证。

### 7. 遮挡与故障恢复不能依赖单个 DOM 选择器

缺陷：插件是原生子视图，宿主 DOM 弹窗不能自然盖住它；隐藏后如果以“当前已显示”为条件检查恢复，就会永远停在隐藏状态。

修订：修正隐藏/恢复状态机，使用真实播放详情状态，加上宿主 modal 状态监听。恢复列表为宿主单独组件，只提供基本加载、播放、分段浏览和刷新，不进入 provider 选择目录。

已实现基本路径。最终验收仍须覆盖所有宿主遮挡层、缩放/全屏/最小化及窗口坐标变化；统一遮挡管理应继续收敛为显式注册，当前仍兼容监听 `.show-modal`。

### 8. 签名预览与安装必须绑定相同字节

缺陷：用户预览权限后，磁盘包可能被同一公钥重新签名并替换。仅检查公钥不变，不能证明安装的是用户预览的内容。

修订：预览返回完整包哈希，确认安装必须匹配该哈希和公钥指纹；预览令牌限时并限制数量。安装数据先在有界解析器中验证，写入独立版本目录，最后原子更新注册表指针。注册表失败时恢复内存记录并删除新目录，保留旧版文件供显式回滚。

已实现并测试更新换钥拒绝、预览包替换、写入失败和重启后回滚。安装/回滚/启用/卸载的存储变更已串行化；卸载同时清理作用域存储。

说明：ZIP 内签名不可能在完全不读取/解压任何成员前验证。原计划的“验证完成后再解压”应解释为“有界读取到内存并验证后才写入安装目录”，或者另设包外签名；当前采用前者。

### 9. 示例密钥不构成正式官方信任根

缺陷：示例私钥可公开，因此任何人都能签出相同身份的包。签名只证明控制了某个私钥，首次信任的指纹并不自动证明作者身份。

修订：生产信任根排除示例公钥。`build:plugins:release` 必须显式提供外部 `LX_PLUGIN_SIGNING_KEY`，拒绝默认示例私钥。打包生成匹配公钥指纹清单。开发样例可以使用示例密钥；签名验证限定为 Ed25519。API 兼容规则采用“相同 major 且所需 API 不高于宿主”，不再只比较 major。

已实现发布门禁；未创建或读取用户正式发布私钥，未完成正式签名发行。

### 10. 分页快照与聚合搜索仍需要来源能力建模

缺陷：远程来源可能有不同 pageSize、总量估算、重复数据和变化的排序。固定 pageSize + 全局 offset 的接口对聚合搜索未必成立；全选 10,000 首也可能触发大量在线请求。

修订：快照补充 pageSize，分页适配器保存自己的当前页和分页缓存。歌单与排行榜使用不修改页面全局 store 的查询接口；搜索读取排队并核对请求上下文。正常翻页后的刷新保持页码。

已完成基本分页修复与真实适配器测试。聚合搜索的稳定 offset/cursor、未知 total、取消、进度和部分失败尚未完成，应补充来源能力描述后再验收在线大规模批处理。

### 11. coverUrl 与禁止插件联网之间存在冲突

缺陷：来源返回的封面通常是 HTTPS 图片。严格 CSP 与 session 网络拦截会阻止插件直接加载，因此卡片不能简单拿到远程 URL 就显示。

修订方向：增加宿主图片代理/资源 broker，插件仅得到本地能力 URL；宿主限定 URL 来源、大小、MIME、重定向和超时，缓存并剥离凭据，不向插件开放任意 fetch，也不能把图片代理变成 SSRF 入口。

本轮保留严格隔离与无封面占位，未通过放宽 CSP 绕过此问题。图片 broker 属于后续未完成项。

### 12. 默认切换必须以行为验收为条件

缺陷：校验函数测试通过，不代表插件已经具备旧页面所有业务行为；模拟快照体积也不能证明 10,000 首真实 DOM 和状态切换正确。

修订：实验开关默认关闭。控制器/适配器/安装事务测试之外，增加真实 Electron 测试，运行实际 preload、协议、主进程请求入口、宿主 gateway 和 CollectionController，数据源使用隔离夹具；另保留真实四类页面、安装包与 GNOME 验收清单。

已建立测试链路并修正通信错误。阶段 3 的完整功能对照、在线真实来源、正式签名包安装以及阶段 4 默认切换仍未完成。
