# 播放详情插件恢复与歌词评论验收

日期：2026-10-20。对象：当前工作区的生产构建及真实 Electron 窗口。

## 结论与边界

播放详情已接入默认启用的官方整合包 `lx.official-suite`，功能 ID 为 `playback.detail`，依赖 `playback`。入口仍为底部播放器的歌曲封面。原版的封面、歌词、播放控制及右侧评论布局保留。

详情控制器位于 `src/renderer/bundles/official/features/shell/PlayDetail.js`；渲染位于 `src/renderer/bundles/official/renderers/shell/PlayDetail.vue`。评论请求与状态控制归入官方包的 `features/shell/PlayDetail/MusicComment.js`。旧 `components/layout/PlayDetail/index.vue` 仅保留指向功能插槽的兼容入口，不能绕过插件启用状态。

歌词与评论是官方整合包中播放详情的内部组件，目前不作为两个可单独安装的插件发布。`classic`、`compact` 两个渲染注册暂时使用同一个原版详情模板；已验证切换过程，但不能据此声称存在两套不同的详情设计。

## 本轮修复

- 评论面板打开即加载热门及最新评论；切歌、关面板、卸载时使旧请求失效。快速连续翻页以最新请求为准，失败最多尝试三次并显示错误状态。已在途的共享 SDK 网络请求可能仍完成，其结果会被丢弃；不会为旧页面继续重试。
- 同一首歌因补全封面、播放元数据而替换对象时更新引用，保留评论及页码，避免无意义地清空并重载。
- 本地歌曲或缺失歌曲信息使用不可用状态。关闭与刷新使用带可访问名称的按钮，隐藏面板不可获得键盘焦点，支持在面板中按 Escape 关闭。
- 搜索与在线列表加入歌曲后，先等待列表提交，再从当前列表查找播放索引，修复首次播放及连续加入新歌曲可能无法播放的问题。
- 咪咕元数据接口原先将 Promise 直接交给 `Promise.all`，读取歌词前就会抛出 `object is not iterable`。改为直接等待批量结果；已有歌词链接直接使用，补查时优先使用版权 ID。封面查询同步处理同一 ID 问题。
- 卸载歌词组件时清理延迟滚动、动画及监听；关闭或禁用详情时清理评论、歌词选择和鼠标隐藏状态。切换渲染方式时不会被旧模板的离场回调错误关闭。

## 自动化与真实窗口验收

使用临时用户目录，仅复制当前已配置的音乐接口配置及用户接口脚本，不修改日常歌单、播放记录、DJ 配置或桌面启动入口。真实音频测试将临时播放器设为静音，实际经过播放、暂停及恢复状态。

`npm run test:play-detail` 覆盖 11 项确定性回归：评论初次加载、旧歌响应、同歌元数据替换、连续翻页、关闭取消后续重试、本地及空歌曲、卸载、失败重试上限、两处列表提交后播放、咪咕元数据与详情生命周期。

`npm run test:play-detail:live` 从最新 `dist/main.js` 启动真实应用并调用实际 SDK；需要当前用户已配置可用的音乐接口。支持 `LX_DETAIL_UI_ONLY=1` 只运行窗口流程，或 `LX_DETAIL_API_ONLY=1` 只运行网络探测。

窗口验收包含：从真实搜索结果播放两首歌、点击封面进入详情、检查实际渲染的歌词和评论行、评论分页及刷新、歌词文本选择、暂停恢复、下一首与评论歌曲同步、评论关闭重开、渲染切换、详情启停及播放器依赖启停。截图同时记录原始大小和 760×650 窗口。

上述窗口流程已全部通过，应用渲染层未记录 TypeError、ReferenceError 或未处理异常。可见性断言同时检查评论区域实际展开，截图已人工查看，确认热门评论、最新评论与原版详情布局实际显示。

最终渲染进程与主进程生产构建均成功；针对性 ESLint、`git diff --check`、音乐接口边界测试通过。官方包和电台包的源代码哈希、签名包、复制到构建目录的包以及宿主内的校验哈希一致。

补充执行完整应用烟测，通过 33 项功能注册、66 项渲染注册、17 项设置贡献、官方整合包与电台包启停恢复，以及真实 SQLite 列表和两种隔离集合视图流程。测试夹具补充临时数据目录、真实应用版本及后台渲染设置，避免空目录和后台窗口干扰验收；详情窗口验收单独前台执行。

当前歌曲的歌词与评论来自真实在线请求。歌曲可能无歌词、无评论或被服务端限制；此时显示空或错误状态属于接口结果，不能把一首歌的成功推广为所有资源均可播放。

测试记录位于 `.runtime/play-detail-20261020/`，保留每次基线与后续验证日志。网络探测只保存状态、数量与耗时，不保存评论、完整歌词、音频链接或密钥。最终结论以 `ui-live-results.json`、`api-results.json`、`unit.log` 及最新构建日志为准，早期失败文件仅供定位历史问题。

本轮构建没有替换 `/opt/lx-music-desktop` 中已安装的程序，也没有发布安装包；已验证的是当前工作区的最新生产构建。
