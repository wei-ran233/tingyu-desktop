# LX Music Desktop —— 项目架构与交互优化重构方案

> **历史原路径**：`doc/项目架构与交互优化重构方案.md`（现位置：`doc/plans/项目架构与交互优化重构方案.md`）
> **优化目标**：优化项目代码结构、统一设计系统 Token、提升界面可用性、简化高频操作路径。
> **涉及范围**：`src/renderer/views/Dj/**`、`src/renderer/composables/useDj*`、`src/renderer/utils/dj/**`、`src/renderer/views/List/**`、`src/renderer/components/common/SvgIcon.vue`、`build-config/tests/**`。

---

## 一、 现状诊断与核心痛点

### 1.1 代码架构痛点
1. **音乐检索与播放逻辑双轨重复（违反 DRY 原则）**
   - `src/renderer/composables/useDjChat.ts` 与 `src/renderer/utils/dj/ai/toolExecutor.ts` 各自维护了一套几乎相同的 `isNonOriginal`（排除翻唱/伴奏/Live）、`pickBestOriginal`（挑选最佳原唱）、多音源检索、封面解析以及播放列表注入逻辑。
   - **性能隐患**：`useDjChat.ts` 具备 5 分钟 TTL 内存缓存和并发相同请求合并（Pending Request Deduplication），而 AI Agent 工具调用使用的 `toolExecutor.ts` 却没有任何缓存，导致大模型连续触发 `search_and_play` 工具时产生重复网络请求。
2. **本地推荐引擎与 AI 工具过滤脱节**
   - `src/renderer/utils/dj/templateEngine.ts` 的 `recommendFromLoveList` 评分固定为 `0.5`，未融合 `userProfile.ts` 中已计算好的偏好歌手、历史播放频次以及天气/时段场景特征词。
   - `src/renderer/utils/dj/ai/toolExecutor.ts` 的 `get_user_favorites` 工具声明了 `moodOrGenre` 参数，但执行时未据此做过滤。
3. **视图层隐藏缺陷**
   - `src/renderer/views/Dj/index.vue` 中推荐历史项的“直接播放”按钮绑定了未导出的 `directPlay(item)`（setup 中重命名为了 `historyDirectPlay` 且未暴露在返回对象中），点击会触发异常。
   - 音乐推荐卡片的黑胶旋转动画绑定在全局 `isPlayingMusic` 布尔值上，导致只要播放过一首歌，对话流中**所有历史推荐卡片**的黑胶唱片都会同时旋转，无法区分当前真正正在播放的歌曲。
   - `src/renderer/views/List/MusicList/index.vue` 批量操作模式下“喜欢”列写死了静态 `❤️` 文本，无实际收藏状态判断与点击交互。

### 1.2 界面设计与交互可用性痛点
1. **高频操作路径过长（需频繁进出设置弹窗）**
   - 用户在收听 AI 电台时，**开关语音播报**、**开关自动连播**、**要求 DJ 切歌推新**是最核心的三大高频操作，原先必须打开“AI 电台设置 → 语音播报”才能切换（至少 3 步点击）。
2. **模型配置流程不够直观**
   - `DjSettingModal.vue` 中虽然定义了 `quickPresets`（一键预设），但在模板中未渲染展示。
   - 当用户选择 `Ollama` 或 `LM Studio` 等免 Key 本地引擎时，界面仍展示必填样式的 API Key 输入框，而“本地模型自动探测面板”却被折叠在 `<details>高级连接设置` 内部，增加了本地模型用户的上手门槛。
3. **音乐卡片与消息气泡操作闭环缺失**
   - AI 推荐的音乐卡片只有“播放”和“稍后播”，缺少**一键收藏到“我的喜爱”**和**音源标识（KW / TX / WY 等）**。
   - 对话消息仅有悬浮删除按钮，缺少**一键复制**与**单条回复语音重播/朗读**能力。
4. **视觉设计系统 Token 一致性问题**
   - 歌单页 `MusicList/index.vue` 与筛选弹窗 `SongFilterModal.vue` 硬编码了 `#ec4141`（网易云红），当用户切换 LX Music 主题色（如翠绿、蓝、紫、暗黑主题）时产生明显的色彩割裂。

## 三、 重构实施详情

### 阶段 1：代码架构收敛与去重 (`toolExecutor.ts` & `useDjChat.ts` & `templateEngine.ts`)
- [x] **统一音乐检索引擎 (`src/renderer/utils/dj/ai/toolExecutor.ts`)**
  - 将 5 分钟 TTL 内存缓存与并发相同关键词请求合并（Request Deduplication）下沉至 `searchMusicTrack`。
  - 统一导出 `searchMusicTrack` 与 `playMusicTrack`，使 Composable 与 AI Agent 工具层共享同一检索与播放实现。
- [x] **消除重复代码 (`src/renderer/composables/useDjChat.ts`)**
  - 移除本地重复的 `isNonOriginal`、`pickBestOriginal`、`doExecuteMusicSearchFull`、缓存 Map 与播放列表注入代码，直接调用 `toolExecutor.ts`。
  - 新增 `isMusicCardLoved(card)` 与 `favoriteMusicCard(card)`，打通推荐卡片与“我的喜爱”歌单的双向联动。
- [x] **增强 AI 工具与本地推荐算法**
  - `toolExecutor.ts` 的 `get_user_favorites` 支持按 `moodOrGenre` 参数对喜爱歌单推荐结果进行实时过滤。
  - `templateEngine.ts` 的 `recommendFromLoveList` 接入 `analyzeUserProfile()`，结合用户偏爱歌手（+0.2）、历史完播频次（最高 +0.15）、以及雨天/晴天/深夜/早晨的场景特征词（+0.15）进行多维加权打分。

### 阶段 2：AI 电台界面与高频操作简化 (`src/renderer/views/Dj/index.vue`)
- [x] **顶栏一键快捷控制区**
  - **连播开关**（DJ 模式）：顶栏一键切换“连播中 / 连播关”，实时持久化设置。
  - **切歌推新按钮**（DJ 模式）：顶栏一键触发 AI 根据当前氛围推荐并播放下一首好歌。
  - **静音/播报切换**：顶栏一键切换当前模式的 TTS 语音播报开关，关闭时立即中断正在播放的语音并恢复主播放器音量。
- [x] **音乐推荐卡片交互升级**
  - **精准播放态识别**：关联播放器真实状态 (`musicInfo` & `isPlay`)，仅当前正在播放的卡片旋转黑胶唱片、高亮主题色边框并显示“播放中”。
  - **一键收藏喜爱**：每张推荐卡片新增 `♥` 收藏按钮，点击直接加入“我的喜爱”歌单并实时高亮。
  - **音源角标**：展示歌曲匹配的音源标识（如 `KW` / `TX` / `WY` 等）。
- [x] **消息气泡操作栏**
  - 新增悬浮操作栏，支持**一键复制**回复内容（带 1.8 秒“已复制”状态反馈）、**单条回复语音朗读**、以及删除消息。
- [x] **侧边栏历史体验补全 (`useDjHistory.ts` & `Dj/index.vue`)**
  - 修复推荐历史点击直接播放按钮的绑定问题（`onDirectPlayHistory`），并在推荐记录下展示歌手信息。
  - 搜索框支持一键清除关键词，列表顶部显示当前分类记录总数与**一键清空当前分类历史**入口。

### 阶段 3：设置弹窗流程简化 (`src/renderer/views/Dj/components/DjSettingModal.vue`)
- [x] **一键服务商预设栏**
  - 在模型连接顶部渲染 `quickPresets`（`OpenCode Go`、`OpenAI`、`Anthropic`、`Gemini`、`DeepSeek`、`Ollama 本地`、`LM Studio`、`智谱 GLM`、`通义千问`）快捷胶囊按钮，点击即刻切换并自动回填默认 Base URL 与模型名。
- [x] **本地模型零门槛配置**
  - 当选择 `Ollama` 或 `LM Studio` 时，自动隐藏无需填写的 API Key 输入框。
  - 将**本地模型自发现面板**从折叠的 `<details>` 中提升至主视图，并在切换或打开弹窗时自动扫描本地 `11434` / `1234` 端口，点击发现的模型即可一键选用。

### 阶段 4：歌单视图主题一致性与交互修复 (`MusicList/index.vue` & `SongFilterModal.vue`)
- [x] **设计系统 Token 统一**
  - 将 `MusicList/index.vue` 与 `SongFilterModal.vue` 中硬编码的 `#ec4141` 替换为 `var(--color-primary)` 与主题透明色阶变量（`var(--color-primary-light-800-alpha-400)`），完美适配所有浅色、深色与自定义主题。
- [x] **批量模式喜爱交互修复**
  - 将批量操作模式下“喜欢”列的静态图标改为根据 `loveList` 动态展示 `♥ / ♡`，并支持点击直接收藏到“我的喜爱”。

### 阶段 5：统一图标系统扩展 (`src/renderer/components/common/SvgIcon.vue`)
- [x] 补充 `heart`（收藏）、`copy`（复制）、`skip`（切歌推新）、`volume`（播报开启）、`mute`（静音）五个矢量图标路径。

## 四、 优化前后对比

| 维度 | 优化前 | 优化后 |
| :--- | :--- | :--- |
| **音乐检索引擎** | `useDjChat` 与 `toolExecutor` 两套重复代码，AI 工具调用无缓存 | 收敛至 `toolExecutor`，全局共享 5 分钟 TTL 缓存 + 并发合并 |
| **本地推荐算法** | 固定 `0.5` 基础分随机抽样 | 结合偏好歌手、播放频次、天气/时段多维加权评分 |
| **高频电台控制** | 需打开设置弹窗 → 切换分类 → 修改开关 → 保存（4 步） | 顶栏提供「连播开关」「切歌推新」「语音开关」一键直达（1 步） |
| **模型配置体验** | 预设未渲染、本地引擎仍需填 Key、自动探测藏在折叠项内 | 顶部一键预设胶囊、本地引擎免 Key 视图 + 自动扫描发现 |
| **音乐推荐卡片** | 所有卡片黑胶同时旋转、无音源标识、无法直接收藏 | 精准识别当前播放曲目旋转高亮、带音源角标与一键收藏 `♥` |
| **消息气泡操作** | 仅支持悬浮删除 | 支持一键复制、单条语音朗读、删除消息 |
| **历史记录管理** | 推荐点播按钮点击报错、无清空分类入口 | 修复直接播放绑定、支持搜索一键清除与分类一键清空 |
| **主题视觉一致性** | 歌单与筛选弹窗硬编码 `#ec4141` 红色 | 全面接入 `--color-primary` 主题色变量体系 |

## 六、2026-10-16 实现核对与补强

本次核对发现，方案阶段 1 至阶段 5 的主要入口已存在于仓库。本轮在既有实现上修复边界问题，没有重做布局或替换现有播放器体系。

- **搜索候选与缓存**：原唱选择遍历各音源的全部返回候选；英文版本标识忽略大小写，并避免将 `Deliver` 等普通单词识别为 Live；去掉空歌手的模糊匹配。共享 5 分钟 TTL 与并发合并继续保留，网络异常不进入缓存，空关键词不发请求。
- **完整喜爱歌单过滤**：在推荐截取前按歌名、歌手、可推断的情绪和曲风筛选；支持“爵士/Jazz”“治愈/温暖”等关键词关联；没有匹配时返回空集合。此能力属于本地关键词规则，不能可靠判断所有歌曲的实际曲风或情绪。
- **推荐排序与画像刷新**：只在评分相同的候选之间随机排序，避免随机起点打散偏好优先级。收藏列表等长替换、歌曲信息变化及手动标签编辑后，画像缓存会刷新。
- **播放与收藏状态**：推荐历史播放只在统一播放入口累计一次；歌单注入失败不计入播放次数。已知歌曲 ID 不同的卡片不再仅因同名显示“播放中”或“已收藏”。收藏按钮采用主题变量并提供可访问名称；歌单批量模式的收藏按钮支持键盘操作。
- **历史与异步状态**：删除当前历史前保留活跃状态判断；清空其他分类不重置当前会话；删除消息前中止流式生成，防止回调写入偏移后的消息。关闭播报后不播放迟到的自动语音；切换模式、切换会话和离开页面时取消正在请求的单条朗读。
- **验证入口**：`npm run test:dj` 已串联三个测试文件，合计 34 项检查；新增 `build-config/tests/dj-music.test.mjs` 覆盖缓存、搜索、筛选、评分、画像刷新、播放计数、流式删除和异步静音。

测试中的模型通信使用本机模拟 HTTP/SSE 服务，搜索、播放器及列表使用隔离的测试端口；这些结果不代表真实服务商凭证、线上音源可用性、实际音频输出或全部主题的人工视觉验收。

另以 `/tmp` 独立配置目录启动真实 Electron，在阻断外部 HTTP/HTTPS 请求的条件下完成 6 项 DOM 交互检查：DJ 快捷区、连播开关、语音开关、预设栏、Ollama 免 Key/发现面板、OpenAI Key 恢复。该检查不包含首次使用协议的签署、截图视觉验收、在线本地引擎探测或音频输出。
