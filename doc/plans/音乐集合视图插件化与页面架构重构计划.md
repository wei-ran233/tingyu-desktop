# 音乐集合视图插件化与页面架构重构计划

## 摘要

此前把“布局修改”理解为工具栏栏位调整，本计划改为以**可替换的音乐集合视图提供器**为核心：搜索、歌单、收藏/用户列表、排行榜共用同一套数据、查询和操作接口，插件可以分别把它们渲染为列表、卡片、海报墙、时间轴等界面。

架构拆成四层：

```text
数据源适配器
    ↓
CollectionController（分页、筛选排序、选择、播放和业务操作）
    ↓ 快照与命令
当前 CollectionViewProvider（默认列表、卡片或第三方视图）
    ↓
CommandGateway（权限、版本、参数和目标校验）
    ↓
CollectionController 执行宿主业务
```

应用侧栏、页面导航和全局播放栏由宿主管理；集合插件接管音乐页面的标题、元信息、操作栏、主体、空状态、错误状态和分页。播放队列规则、收藏、下载、歌单写入等业务始终由宿主执行。

## 核心接口与约束

新增稳定类型，插件只能接触摘要数据和 opaque key，不能取得内部音乐对象：

```ts
type CollectionSurfaceId =
  | 'search-music'
  | 'list-music'
  | 'songlist-detail-music'
  | 'leaderboard-music'

interface MusicItemSummary {
  key: string
  name: string
  singer?: string
  album?: string
  interval?: string
  source?: string
  coverUrl?: string
  qualityTags?: string[]
  available: boolean
}

interface MusicCollectionSnapshot {
  revision: number
  surfaceId: CollectionSurfaceId
  contextId: string
  title?: string
  subtitle?: string
  coverUrl?: string
  total: number
  loadedCount: number
  page?: number
  pageCount?: number
  selection: { mode: 'none' | 'some' | 'all'; count: number }
  playingKey?: string
  query: { sort?: unknown; filters?: unknown }
  facets: CollectionFacet[]
  commands: CommandDescriptor[]
  status: 'idle' | 'loading' | 'ready' | 'empty' | 'error'
  error?: { code: string; message: string }
}

interface CollectionViewProvider {
  id: string
  displayName: string
  pluginId: string
  apiVersion: string
  surfaces: CollectionSurfaceId[]
  entry: string
  icon: string
}
```

插件 API 固定为 `ready()`、`getSnapshot()`、`getItems({ revision, offset, limit })`、`dispatch(command)`、`getCommandOptions()`、`subscribe('snapshot'|'theme'|'locale'|'availability')` 和作用域存储。单次 `getItems` 最多返回 100 条，歌曲被选中时只返回该条的 `selected` 状态。

选择全部 10,000 首歌曲时，快照只包含选择模式和数量，不序列化全部 key。批量命令使用 `target: { kind: 'selection' }`，宿主自行解析目标，避免大消息和插件伪造 key 集合。

命令白名单包括：`playItem`、`playCollection`、`playNext`、`playLater`、`select`、`selectAll`、`clearSelection`、`setSort`、`setFilters`、`setPage`、`loadMore`、`refresh`、`toggleLove`、`addToPlaylist`、`moveToPlaylist`、`download`、`removeFromCurrentList`、`replaceSource`、`dislike`、`searchItem`、`openSourceDetail`。

命令网关校验插件视图身份、能力声明、快照 revision、当前上下文、目标 key 和参数。歌单目的地、下载音质和换源选项由 `getCommandOptions()` 返回受限的 option ID；删除等破坏性操作由宿主原生确认框确认。过期 revision 返回 `STALE_SNAPSHOT`，插件重新取快照后再提交。

统一 `PageDefinition` 驱动路由、侧栏入口、标题、图标、排序、可见条件、懒加载和宿主/插件来源。内置页面和插件页面使用同一注册表；插件页面路由为 `/plugins/:pluginId/:pageId`，插件被禁用或版本不兼容时自动从导航移除。

## 实施变更

**集合控制器与适配器**

- 为搜索、默认/用户/收藏/本地列表、在线歌单详情和排行榜建立适配器，分别包装现有搜索、列表和排行榜数据接口。
- 将现有页面 composable 中的筛选、排序、分页、选择、播放、收藏、下载、添加/移动、删除、换源和详情跳转迁入控制器，由控制器继续调用现有播放器和 store。
- 适配器输出统一摘要和 facet；插件提交排序、过滤、分页命令，宿主生成新 revision。
- 第一阶段覆盖四个 `CollectionSurfaceId`。搜索中的歌单/歌手列表、列表管理侧栏和下载任务页继续由宿主实现；下载任务属于任务状态，不套用音乐集合接口。

**视图切换与回退**

- 设置中保存全局默认 provider，并允许按四个音乐页面分别覆盖。解析顺序为页面覆盖、全局默认、官方列表插件、最小恢复列表。
- 官方默认列表以签名插件交付，并使用与第三方插件相同的 API；宿主只保留不进入选择列表的恢复列表，用于插件崩溃、禁用、版本不兼容和首次加载失败。
- 提供签名的示例卡片插件，覆盖全部四类音乐页面，用于验证同一功能接口可切换为卡片展示。
- 插件内容放在独立 `WebContentsView` 中。宿主通过占位区域和 `ResizeObserver` 同步 x/y/width/height，并在路由切换、窗口缩放、全屏、最小化及播放详情等宿主遮挡层出现时隐藏视图。
- 每个集合 surface 当前选中的 provider 在会话内保留视图；切换时隐藏并保留选择和滚动锚点。插件连续两次在 60 秒内崩溃后退回恢复列表，停止自动重试，提供重试和更换视图入口。
- 集合相关菜单和弹窗在插件内容区内渲染，通过命令网关执行；宿主界面需要覆盖插件区域时由统一遮挡管理隐藏插件视图。

**页面、主题与插件运行时**

- 侧栏不再硬编码页面，改为渲染 `PageDefinition`；现有页面先完成注册表迁移，再接入插件页面。
- 插件页面也运行在独立视图，可订阅主题、语言和可用状态，通过受限 `navigate` 命令打开宿主页面，使用插件专属存储。
- 新增 `--lx-*` 语义主题变量，包括背景、表面、文本、弱文本、边框、主色、悬停、选中、危险色、圆角、间距和阴影；现有 `--color-*` 通过兼容映射继续工作。
- `ThemeSnapshot` 包含 revision、明暗模式和完整 token。系统主题变化、用户换肤、主题编辑器预览和插件主题变化都会实时推送，无需重载插件视图。
- 插件主题只能贡献受校验的 token 集合；插件页面内部样式不能选择或修改宿主 DOM。旧主题、自定义主题和背景图继续保留。
- `.lxplugin` 使用 ZIP 分发，包含 manifest、页面/集合入口、静态资源、图标、主题和签名文件。manifest 声明插件 ID、semver 版本、API 版本、权限、页面和 provider。
- 使用 Ed25519 签名。首次安装展示发布者公钥指纹和权限；更新必须沿用原公钥，密钥变化直接拒绝。宿主内置官方公钥，第三方插件使用首次信任记录。
- 验证完成后再解压，拒绝路径穿越、符号链接、超限文件数、异常压缩比和未声明入口；新版本先写入临时目录，成功后原子替换，并保留旧版本供失败回滚。
- 插件视图启用 `contextIsolation`、`sandbox`、禁用 Node 和远程导航，通过自定义 `lxplugin://` 协议加载本地资源，设置严格 CSP，只暴露窄化 preload API。宿主绑定 IPC sender 与插件视图，禁止访问任意文件、任意 IPC 和主界面 DOM。
- 生产环境只允许安装签名包；开发构建通过显式启动参数加载未签名目录。卸载时同时清理插件作用域存储。第一阶段不做在线插件市场。

**DJ 与现有功能**

- 将 DJ 页面拆为推荐/模型、TTS/语音、播放控制、历史与用户画像 composable，以及页面区块和设置弹窗组件。
- DJ 保留现有 AI 推荐、模型配置、TTS 和语音播放行为，继续使用 `test:dj` 回归测试；第一阶段不把 DJ 集合改成通用音乐集合插件。

## 分阶段交付

1. 建立类型、CollectionController、四个数据适配器和 PageDefinition；通过内部开关保持现有页面行为，完成命令和分页契约测试。
2. 实现隔离插件视图、签名安装器、插件管理、插件页面和动态主题；交付可切换的卡片示例插件。
3. 将官方列表插件迁移到同一协议，完成四类页面功能对照；宿主恢复列表只在故障时启用。
4. 将官方列表插件设为默认 provider，移除页面内重复的列表渲染逻辑，并保留一个发布周期的内部回滚开关。DJ 拆分可在步骤 2 之后独立合入。

## 测试与验收

- 契约测试覆盖 revision 过期、选择全部、批量目标解析、能力拒绝、option ID 伪造、非法 key、视图身份冒用和超大消息。
- 安全测试覆盖签名篡改、更新换钥、Zip Slip、符号链接、路径穿越、压缩炸弹、协议越权和 Node/远程导航不可用。
- 端到端验证全局 provider 与四个页面覆盖设置、恢复链、插件启用/禁用/更新/卸载、插件页面导航和状态恢复。
- 对现有搜索、默认/用户/收藏/本地列表、歌单详情和排行榜执行操作对照：播放、全部播放、稍后播放、选择、过滤排序、分页、收藏、添加/移动、下载、删除、换源、搜索歌曲和打开来源详情。
- 使用 10,000 首列表验证首屏不传输全量数据、单次最多 100 条、DOM 虚拟化、全选命令消息大小受限、选中状态和滚动锚点在切换后保持。
- 验证窗口缩放、路由切换、全屏、播放详情遮挡和插件崩溃时的 view bounds、隐藏与恢复。
- 验证系统明暗切换、普通主题、自定义主题、插件主题和主题预览在集合视图及插件页面中实时生效。
- 额外并行试运行 CardView、列表、海报墙等布局：插件可分别用于音乐列表、卡片、海报墙、时间轴等；官方列表插件与卡片插件也必须使用同一命令和选择接口。
- 完成 `lint`、renderer/main/plugin 构建、插件包安装验证和现有 `test:dj`；桌面端执行一次真实 GNOME 窗口启动与交互验收。

## 假设与默认值

- 全局应用外壳、侧栏和播放栏由宿主控制；本计划中的布局扩展指音乐页面内容区的视图提供器。
- 音乐页面插件接管集合标题、工具栏、主体、空状态、错误状态和分页，宿主只提供内容区域边界。
- 第一阶段不纳入下载任务页、搜索歌单/歌手结果、列表管理侧栏和播放队列页面。
- 官方列表插件进入视图选择列表；宿主最小恢复列表不供用户选择。
- 第三方卡片插件作为示例交付，不增加内置卡片视图。
- 不提供在线插件市场。插件页面不开放任意网络访问；需要外部数据时后续通过显式网络权限和域名白名单扩展。
- 主窗口现有 Node 安全配置不在本期翻转；插件安全依赖独立隔离视图，插件代码不会进入主渲染进程。
