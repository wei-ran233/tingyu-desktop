1. 先明确事件方向、作用域、订阅身份、事件数据边界和投递语义。默认不提供历史重放、持久化或事务保证；若需要应另立契约。本轮 API 为1.6.0，源码与本地构建已更新，未正式发布。
2. 分开运行时内部通知与公共 event 扩展；复用生命周期的有效实例检查与撤销机制，不让旧实例向新实例继续投递。
3. 实现受限发布/订阅桥接与最小样例，不开放任意频道、任意网络或跨插件对象访问。
4. 新增契约检查和真实 Electron 隔离试点，覆盖权限、依赖、顺序、队列上限、取消、停用与崩溃；整合后更新 SDK 和本页状态。

## 维护与完成判定

- 状态分为“未实现”“部分完成”“已有实施”“本轮验收通过”。只有明确记录执行日期、命令、环境、产物与结果，才能标记本轮验收通过。
- 旧阶段的检查数量保留在原验收记录，本页不累加为本轮进展；已有能力除非出现新风险或回归，不重复作为新交付。
- 每次完成 E1–E7 的增量，更新本页对应行，并链接具体 SDK 和验收记录。原始集合计划保持原文，历史验收结论以新增日期记录补充。
- 本清单不构成提交、推送、系统安装、发布或真实配置修改的授权；执行范围按当次任务确定。
