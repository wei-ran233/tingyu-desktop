# 插件可选依赖与冲突实现计划

[计划索引](README.md) · [后续清单](当前计划状态与后续实施清单-2026-10-21.md)

本轮推进 E4，代码与临时 profile 验收；不包含安装、提交、推送、发布或真实用户配置变更。

## 契约与实现边界

- API 1.9 新增 `optionalDependencies`、`conflicts`，沿用必需依赖的最小包含/最大不包含版本范围。每类最多 32 项，拒绝自身、重复及三类间重复 ID；旧清单签名语义保持。
- 可选依赖不参与核心激活排序，不传播核心停机；仅在目标运行且依赖版本、扩展点版本、schema 和权限有效时接入声明式贡献。目标缺失、故障、卸载、替换和范围失配时撤下集成，A 的独立运行时保持；目标恢复后自动接入，无任意跨插件调用。
- 必需循环继续阻塞；可选循环没有激活排序边，双方核心启动后可互相贡献。混合依赖中的必需边仍有强制顺序。
- 冲突任一方向命中版本范围、双方启用且兼容时同时阻塞。禁用其中一个解除冲突；不自动选择赢家，不修改用户开关。必需依赖者继续受阻塞传播影响。
- 设置和管理页显示可选集成状态与具体原因；安装确认增加关系声明。完整升级影响评估保留为 E6。

## 工作与验收

1. 清单/依赖解析及契约测试：限定子 agent 处理 common 文件与新测试。
2. 生命周期贡献门控、即时取消与服务目录：主 agent；独立运行时与集成撤销区分。
3. 设置/管理/安装确认展示：独立子 agent，仅改两个 Vue 文件。
4. 主 agent 审阅差异，运行契约、类型/风格与生产构建；临时 profile 使用真实签名包和隔离运行时验证缺失、恢复、禁用、更新、卸载、故障和冲突。
5. 独立审查后修复并复核；更新 SDK、索引、清单与验收记录，保留历史证据。
