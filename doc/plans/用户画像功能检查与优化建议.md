# 用户画像检查与优化思路

本次仅检查和提出方案，不迁移或清空现有画像数据，不自动调用外部模型生成新画像。

## 现状判断

保留“音乐偏好辅助推荐”的方向，但当前数据可信度、反馈闭环与界面语义不够准确，暂不应展示为深度心理画像。

1. `userProfile.ts` 用歌名和歌手的关键词猜曲风、情绪、语种。普通歌曲没有曲风关键词时无法可靠归类；单个“梦”“日”等字和歌手名称可能导致误判。未知应保持未知。
2. 未识别到偏好时填入固定曲风；没有歌手时把周杰伦、陈奕迅、林俊杰写入提示词。这些是默认推荐策略，却被呈现为用户偏好。
3. 播放入口 `ai/toolExecutor.ts::playMusicTrack` 和播放器 `usePlayer.ts::handleCanplay` 都调用 `recordPlayedSong`。同一首经工具播放可能重复计数；canplay 表示资源就绪，无法证明用户听了多久或喜欢它。
4. 收藏数和播放次数直接相加；播放数据没有来源、时间戳、收听时长、跳过／不喜欢反馈和时间衰减，自动推荐反复播放可能强化自己的推荐结果。
5. 手动标签与自动推断结果直接取并集。删除手动标签不能排除同名自动标签，没有“以后不推荐”的独立约束。
6. 百分比主要在关键词命中的小样本内部归一化，界面缺少识别覆盖率与依据；学习样本数只报告收藏数量，未涵盖播放事件口径。
7. 时段函数是固定曲风映射，当前存储并没有记录每次听歌时间，因此它是场景规则，不是学习出的时段偏好。
8. 本地缓存和 localStorage 不是完整的响应式画像状态，设置页 computed 对播放或标签更新的刷新存在滞后风险。
9. 历史 AI 摘要可被作为“长效 AI 深度心理与审美画像”注入提示词，当前代码未发现生成摘要的调用入口，也没有有效期、来源或确认机制。听歌偏好不应被直接解释为人格特征。

## 建议的数据分层

| 层级 | 数据 | 使用方式 |
|---|---|---|
| 用户明确偏好 | 喜欢／不喜欢的歌手、曲风、语种；屏蔽歌曲 | 明确约束，允许编辑、撤销、暂停个性化 |
| 近期行为 | 实际收听时长、完成、主动重播、快速切歌、收藏 | 有时间戳、来源、去重标识；近期信号更重要 |
| 当前会话 | 本轮想听的风格、情绪、活动 | 优先满足当前请求，不自动变成长久偏好 |
| 场景信息 | 时间、天气 | 弱提示，标记为场景建议，不等于用户偏好 |

## 实施顺序

第一阶段：纠正语义与明显的数据错误。

- 将页面称为“音乐偏好”；移除没有证据的固定个人标签和默认歌手，将空状态写成“还不了解你的偏好”。
- 在播放器统一记录事件，撤除工具层的计数。资源就绪不计入有效收听；收听阈值可先采用 30 秒或歌曲时长的 30%（取较小值）作为可调试验参数，并防止暂停、拖动和资源重载重复计数。
- 手动设置优先，区分喜欢、不喜欢、未知；加入排除集合，自动分析不能覆盖明确屏蔽。
- 每个标签显示来源、样本数量、最近更新时间和“纠正／不感兴趣”操作；推断标签明确标成待确认。

第二阶段：引入轻量行为事件，保持本地计算。

- 用版本化事件记录 `trackIdentity / source / startedAt / listenedMs / completion / action / origin / sessionId`，设置保留期限和聚合清理。
- 收藏、主动重播、完整收听作为不同强度正信号；快速跳过作为弱负信号，用户明确“不喜欢”作为强约束。
- 区分用户主动选曲与 AI 自动播放；后者降低学习权重，避免自我强化。
- 将近期偏好与长期偏好分开；没有足够证据不做曲风或语种百分比，不从歌手姓名推断语种。

第三阶段：形成推荐反馈闭环。

- 当前请求和屏蔽规则优先，然后综合长期／近期偏好、已听去重、歌手多样性和少量探索。
- 同一首、同歌手、同曲风设置连续推荐上限，避免越推越窄。
- 推荐旁提供“为什么推荐”：只引用可追溯证据，例如“最近主动重播过这位歌手”。
- AI 摘要仅作可编辑的音乐偏好摘要；提供是否发送给模型的开关，不生成心理或人格结论，不让旧摘要覆盖当前请求。

## 验收建议

- 工具点歌到真正播放只产生一条有效收听；快速切歌不被计成强喜欢。
- 删除或屏蔽标签后，重新分析、重启应用均不自动加回。
- 没有数据时不显示伪造偏好或占比；小样本显示“数据不足”。
- 不同来源的同一首歌能去重，合作歌手分别归一化。
- 当前“想听摇滚”不会被昨天的安静偏好压过。
- 以跳过率、有效收听率、收藏／不喜欢反馈与歌手多样性验证效果，避免只看调用成功率。
