# 插件数据提供器 SDK 1.4

API 1.4.0 增加通用 `provider` 数据提供器，并兼容旧 API 包。`processor` 按顺序处理同一种模型；`provider` 从一个选中的插件取得模型，输入和输出可以不同。两者都通过有界数据契约工作，不能传入 DOM、函数或宿主对象。

## 声明与依赖

扩展点拥有者 B 在 `extensionPoints` 中声明 `id`、`version`、`kind: "provider"`、`input`、`output`。实现者 A 需要：

- 声明 `apiVersion: "1.4.0"`、`runtime.entry` 和 `extensions.provide` 权限。
- 在 `dependencies` 中声明 B，可限定包版本区间。
- 在 `extensions` 中声明 `id`、`target: "B的ID/扩展点ID"`、扩展点 `version` 和运行时 `handler`；可设置 `priority`。

A 必须等待 B 激活，且扩展点版本与权限检查通过后才能激活。B 缺失、停用、失败或版本不兼容时，A 阻塞；停止顺序为 A 再 B。插件自行声明权限不代表能访问任意宿主 API，安装仍校验签名和授权。

## 选择与执行

宿主通过 `PluginLifecycle.provide(target, input)` 调用。只有 active 插件的实现进入候选，按 `priority` 升序（默认 0），再按插件 ID 和扩展 ID 排序；每次只调用第一名，不合并多个结果。无可用实现时返回 `null`。

调用先验证输入，再验证输出。处理限时 2 秒；参与实例停止、替换或选中的提供器变化时，旧结果被拒绝。无关插件变化不取消请求。初始化、超时、崩溃或非法输出会隔离相应插件，直到显式重新初始化、重新启用或更新。

提供器失败时，当前调用抛错，不在同一次请求中静默调用其他提供器；下一次请求可以选中剩余的健康实现。宿主决定空结果和错误时的正常显示行为。

运行时使用签名包、独立沙箱及权限限制，不提供 Node、任意 IPC、网络或跨插件资源访问。handler 从上下文获取本插件设置快照，可通过 `isCancelled()`、`onCancel()` 感知取消。

## 数据契约

支持有限的 string、number、boolean、object 和 array schema。数组写法：

```json
{"type":"array","maxItems":12,"items":{"type":"string","maxLength":100}}
```

数组 `maxItems` 必须为 1–32；对象最多 16 个字段；字符串 `maxLength` 为 1–4096；schema 校验从深度 0 开始，最大深度为 4。非法元素、超长数组及额外对象字段会被拒绝。runtime 响应消息总大小上限为 64 KiB，不因 schema 允许嵌套而放宽。对象 schema 的字段声明顺序不影响结构兼容性。

## 搜索灵感试点

官方功能包提供 `lx.official-suite/search.suggestions`，点版本为 `1.0.0`：

- 输入：`{source: string}`，字符串最多 32 字符。
- 输出：`{suggestions: string[]}`，最多 12 项，每项最多 100 字符。
- 宿主将无实现的 `null` 转为 `{suggestions: []}`；失败时页面保留现有热搜、历史记录和手动搜索。

样例 `plugin-samples/search-starters/` 的插件 ID 为 `lx.search-starters`，默认关闭。用户在统一插件设置中启用“搜索灵感”，编辑 `queries` 字符串，用分号或换行分隔。样例去除空项与重复项，并限制条数及长度；不读取历史记录、歌单、凭据或网络数据。

插件只提供数据。搜索功能负责加载和刷新数据，页面组件负责按钮显示与点击搜索。原版和潮汐已通过实机验证，复用同一功能逻辑和空白页组件；停用时清除显示，原设置保留。界面文本使用普通文本绑定，不执行插件提供的 HTML。

## 验收与边界

当前实现通用 processor 和 provider；通用 action/event、动态 renderer/slot/toolbar 注册、动态主题 assets/layout/motion 协议、可选依赖、配置迁移和凭据存储仍待实现。

实机、契约和构建结果见 [数据提供器验收记录](../records/插件数据提供器验收-2026-10-21.md)。前阶段运行时约定见 [SDK 1.3](插件运行时与功能增强SDK-1.3.md)。

## 2026-10-21：设置实时同步与请求一致性

已统一设置提交后的宿主和隔离页面通知，并增加设置修订的取消控制。相关参数变化会取消旧快照调用，保留运行实例，由新请求读取新参数；无关调用继续执行。打开的设置表单与搜索灵感会实时刷新。该协议为宿主内部通知，通用 event 扩展仍待实现。详见 [本轮实现与验收](../records/插件设置实时同步与请求一致性-2026-10-21.md)。

## 2026-10-21：恢复默认与请求合并

已提供统一插件参数恢复入口，清除本插件的覆盖值并复用参数同步/取消机制；不会改变启用状态或其他插件设置。实机发现并修复了连续通知导致的重复加载和“运行时繁忙误隔离”问题。71 项契约、17 组生命周期与 7 组设置场景通过。详见 [实现与验收记录](../records/插件参数恢复默认与请求合并验收-2026-10-21.md)。本轮未增加通用 action/event 或新的公共插件 API。
