# 文档维护约定与路径迁移

[指南索引](README.md) · [文档总索引](../README.md)

## 分类规则

| 内容 | 位置 | 维护方式 |
| --- | --- | --- |
| 仓库概览与主要入口 | 根 README.md | 保持简洁，不堆放具体服务接入和历史日志 |
| 开发、agent、验证等可复用流程 | doc/guides/ | 随当前代码修订 |
| 当前职责与源码入口 | doc/architecture/ | 与目录迁移同步，写明核对日期 |
| 版本化扩展契约 | doc/plugins/ | 标明 API 版本、兼容条件和对应实现 |
| 用户可见行为与排障 | doc/features/ | 写明配置入口、默认行为和适用环境 |
| 原始设计、分期方案、建议 | doc/plans/ | 保留原始约束，链接后续验收，不冒充完成状态 |
| 某轮审计、实施、验收 | doc/records/ | 文件名保留主题与日期，保留失败和剩余问题 |
| 公开图片 | doc/images/ | 保留资源语义，避免敏感或误导性截图 |
| 样例或测试的就近入口 | plugin-samples/README.md、build-config/tests/README.md | 解释目录用途，链接主文档，不复制整套指南 |

每个分类目录必须有 `README.md`，至少包含：目录用途、阅读顺序或任务入口、全部正文文档的链接、适用范围以及新增文档的归属规则。新增正文后同步更新所属分类索引，重要入口再加入总索引。

## 内容与状态

- 文档正文主要用中文，API 标识、字段与命令保持源码拼写。
- 当前指南标明核对日期；SDK 标明 API 版本；计划说明其性质；验收记录写清实际执行范围和未完成项。
- 同一文件混有计划和后续实施时，在分类索引解释其性质。不要从标题中的“实施”“验收”推断所有阶段完成。
- 使用仓库相对链接，源码链接优先指向稳定定义与入口；避免依赖容易漂移的行号。
- 历史源码路径、命令和本机证据路径可以保留用于追溯；当前操作指南必须指向有效入口。
- `.runtime/`、`/tmp/`、本机绝对路径不是随仓库分发的证据。需要复现时核对原环境和文件是否仍存在，不捏造替代结果。
- 第三方 README、LICENSE 和法律文本保留归属，不作为项目指南改写。

## 更新检查

1. 新目录添加 README，并从上一级索引链接；新增正文加入所属分类索引。
2. 检查 Markdown 链接和 HTML 图片资源是否相对当前文档解析；迁移时同时修复跨目录链接。
3. 核对文档中的 npm 入口与 package.json.scripts、源文件路径与当前工作区一致。
4. 运行 `git diff --check`，检查工作区原有改动是否保留；只改文档通常无须重建应用或运行外部服务。
5. 报告本轮实际做了哪些检查。历史验收正文只修正导航和相对链接，结论变更另附日期记录。
